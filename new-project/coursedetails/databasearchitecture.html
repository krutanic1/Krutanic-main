🗄️ Database Architecture in 2 Weeks

⏱️ 1 hour/day (Mon–Sat) + Sunday assessments & projects

From relational design to indexing, transactions, and NoSQL — job‑ready skills for backend, data engineering, and DBA roles.

📅 Week 1 – Relational Database Architecture
MondayDB Fundamentals & Architecture
🎯 1h: What is a database? DBMS vs file system. Components: query processor, storage manager, buffer manager. Client‑server vs embedded.
TuesdayRelational Model & Schema Design
🎯 1h: Relations, attributes, tuples, keys (primary, foreign, candidate). ER diagrams → relational schema. Practical: draw ER for “library” system.
WednesdayNormalization (1NF, 2NF, 3NF, BCNF)
🎯 1h: Anomalies (update/insert/delete). Functional dependencies. Normalize a denormalized table to 3NF. Avoid redundancy.
ThursdaySQL Deep Dive (DDL, DML, Joins)
🎯 1h: CREATE, ALTER, DROP. INSERT, UPDATE, DELETE. INNER/LEFT/RIGHT/FULL JOIN. Practice on sample schema (employees, departments).
FridayIndexing & Performance
🎯 1h: Clustered vs non‑clustered indexes. B‑tree vs hash. When indexes hurt performance. EXPLAIN plan basics.
SaturdayViews & Stored Procedures
🎯 1h: Create and manage views (security & simplicity). Stored procedures vs functions. Write a simple procedure with parameters.
🌿 SUNDAY – Project 1: Library DatabaseNormalization + SQL
✅ Build a normalized library management schema
➤ Create ER diagram → tables: Books, Members, Loans, Authors.
➤ Ensure 3NF. Define primary/foreign keys.
➤ Write 5 SQL queries: list overdue books, most active member, etc.
➤ Create an index on “loan_date”.
➤ Deliver: SQL script + screenshot of query results.
📝 Assessment: 15 MCQs (normal forms, indexes, joins, keys).
⚡ Week 2 – Transactions, NoSQL, Warehousing
MondayACID & Transactions
🎯 1h: Atomicity, Consistency, Isolation, Durability. BEGIN/COMMIT/ROLLBACK. Concurrency problems (dirty read, phantom read).
TuesdayIsolation Levels & Locking
🎯 1h: Read Uncommitted, Read Committed, Repeatable Read, Serializable. Optimistic vs pessimistic locking. Deadlock handling.
WednesdayNoSQL Architecture Overview
🎯 1h: When to use NoSQL. Document stores (MongoDB), key‑value (Redis), column‑family (Cassandra), graph (Neo4j). CAP theorem (Consistency, Availability, Partition tolerance).
ThursdayData Warehousing & Star Schema
🎯 1h: OLTP vs OLAP. Fact table, dimension table. Star schema vs snowflake. Basic ETL concepts.
FridayDatabase Sharding & Replication
🎯 1h: Horizontal vs vertical sharding. Master‑slave replication. Read replicas for scalability. Trade‑offs and consistency issues.
SaturdayBackup, Recovery & Security
🎯 1h: Backup types (full, incremental). Point‑in‑time recovery. Role‑based access control, encryption at rest/in transit. Audit logs.
🌿 SUNDAY – Final Project: E‑Commerce Database ArchitectureFull design + NoSQL integration
✅ Design a hybrid database solution for an online store
➤ Relational part (PostgreSQL): users, orders, products, inventory (3NF).
➤ Write transactions for order placement (ACID).
➤ Add a Redis cache for product views (key‑value).
➤ Propose a sharding strategy for orders table.
➤ Deliver: schema diagram, SQL transaction scripts, and a 300‑word explanation of trade‑offs.
📝 Final Assessment: 20 questions (ACID, isolation, NoSQL, sharding, warehousing) + 2 real‑world design scenarios.
